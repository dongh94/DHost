# DHost 제품 요구사항 정의서

문서 버전: PRD v1.0 통합 검토본  
정책 확정 기준일: 2026년 11월 5일  
문서 작성일: 2026년 11월 5일  
공식 앱명: **DHost**  
과거 가칭: CloudTerm  
문서 상태: 확인 가능한 결정 통합 완료, STEP 01~07 원문 대조 대기

## 1 문서 목적과 적용 원칙

이 문서는 DHost의 제품 방향, 정책, 개발 범위, 보안 기준, 미결정 사항 및 검증 기준을 하나의 개발 기준 문서로 관리하기 위한 것이다. CloudTerm이라는 과거 가칭으로 이루어진 결정은 제품명 변경만으로 취소되거나 변경되지 않는다.

**완전성 제한:** 참조 대화에서 STEP 08 사용자 확정문과 이후 통합 요약, 이름 변경 및 개발 준비 대화는 확인되었다. STEP 01~07의 개별 상세 원문은 반환되지 않았고, 통합 요약의 ‘STEP 01~08 통합 요구사항’과 ‘출시 전 필수 테스트’ 본문도 비어 있다. 따라서 본 문서는 누락 없는 최종 승인본으로 취급하지 않는다. 원문 부재는 정책이 미확정이라는 뜻이 아니며, 기존 결정의 내용을 아직 대조하지 못했다는 뜻이다.

### 1.1 결정 상태

| 상태 | 의미 | 적용 방식 |
|---|---|---|
| 직접 확정 | 조회 가능한 사용자 발언 또는 현재 요청에서 명시적으로 결정 | 확정 정책으로 적용 |
| 기존 확정 요약 | 이전 답변이 기존 확정 정책이라고 명시한 내용 | 유지하되 상세 원문 대조 필요 |
| 제안 | 이전 답변의 추천·보완안·개발 초기안 | 승인 없이 확정 정책으로 승격하지 않음 |
| 미결정 | 이전 대화가 상세 정의 필요 또는 미확정으로 표시 | 설계 결정 필요 |
| 원문 확인 필요 | 상세 내용 또는 확정 근거를 조회하지 못함 | 임의 복원하거나 새로운 요구사항으로 대체하지 않음 |

이 문서에서 새로 부여한 식별자는 추적을 위한 편집용 ID이며, 기존 대화의 원래 요구사항 번호를 의미하지 않는다. 검증 절차를 구체화한 항목은 시험안으로 표시하며, 테스트 통과를 의미하지 않는다.

## 2 제품 정의

DHost는 여러 Linux 서버 및 SSH 지원 장비에 접속하여 작업하는 범용 SSH 데스크톱 클라이언트다. 특정 인프라 플랫폼에 종속되지 않는 것을 제품 방향으로 한다. 고객사와 서버를 찾고 연결하는 접속 관리, 일반적인 SSH 작업을 수행하는 터미널, 인증정보와 운영 서버 보호, 다중 세션과 경유 접속을 통한 업무 효율이 핵심 가치다. [S2, S4]

OpenStack·Kubernetes 운영 기능은 장기 확장 대상으로 언급되었다. 초기 제품의 필수 기능으로 해석하지 않는다. 최초 개발 및 배포 대상은 macOS M2이며 Windows·Linux는 후속 대상이다. [S1, S2]

## 6 개발 범위와 릴리스 구분

**PRD v1.0은 문서 버전이며 제품 v1.0 출시 완료를 의미하지 않는다.** S2는 MVP와 첫 정식 릴리스를 구분하는 개발 순서를 추천했다. 아래 표는 그 범위안을 보존한 것이며 전체 로드맵의 별도 사용자 승인은 조회되지 않았다. 다만 단일 Jump Host의 첫 버전 포함과 플랫폼 우선순위는 각각 기존 확정 요약 및 직접 확정 정책에 근거한다.

| 단계 | 목적 | 제시된 범위 | 결정 상태 |
|---|---|---|---|
| MVP | 직접 접근 가능한 Linux 서버에서 일상 SSH 작업 검증 | 고객사·서버 관리, 안전한 SSH 연결, 터미널, 다중 탭·세션, 기본 보안, 로컬 저장, 한국어 UI·테마 | S2 개발 범위 제안 |
| 제품 v1.0 | 첫 정식 릴리스 | MVP 전체, 단일 Jump Host, 기존 SSH 설정 경유 연결, 오류 진단, 기본 백업·복원, 보안 검증·배포 | 단일 Jump Host 첫 버전 포함은 기존 확정 요약, 나머지 배치는 범위안 |
| v1.x | 후속 실무 기능 확장 | SFTP, 화면 분할, Local Port Forwarding, 앱 잠금, 다양한 터미널 사용자 설정 | S2 후속 범위안, 세부 버전 미정 |
| v2.0 이후 | 플랫폼·운영 기능 확장 | 다중 Jump Host, 추가 포트 포워딩, Windows·Linux, 선택형 OpenStack·Kubernetes 운영 기능 | S2 장기 범위안, Windows·Linux 후속 지원 자체는 직접 확정 |

영어 UI는 후속 지원으로 확정되었지만 특정 릴리스에 배정되지 않았다. MVP 완료를 정식 배포 승인으로 간주하지 않는다. 장기 확장 항목을 초기 버전 필수 기능으로 끌어오지 않는다.

### 7.2 기존 대화의 보완 제안

다음 항목은 S2의 ‘추가 보안 규칙’ 및 ‘권장 보완안’이다. 기존 정책을 구체화하려는 제안이며 별도 승인 없이 확정 정책으로 표시하지 않는다.

| ID | 보완 제안 | 필요한 상세 결정 |
|---|---|---|
| SEC-P01 | 호스트 검증을 대상 서버와 Jump Host 모두에 적용하고 신뢰할 수 있는 경로로 지문 대조 안내 | 각 단계 UI 및 신뢰 저장 방식 |
| SEC-P02 | SSH 설정 우선순위와 최종 적용값·출처 표시 | 앱 설정과 기존 SSH 설정 충돌 규칙, 보안 약화 설정 처리 |
| SEC-P03 | 자격증명을 고객사·대상·계정별로 구분 | 경유 경로 포함 여부, 저장 및 재사용 범위 |
| SEC-P04 | 접속 이력은 서버 식별자·접속 및 종료 시각·성공 또는 실패 상태로 제한하고 명령·출력은 제외 | 보관 기간, 삭제, 접근 권한, 진단정보 정책 |
| SEC-P05 | 운영 서버 표시와 앱이 직접 실행하는 위험 동작의 명시적 확인 중심으로 보호 | 붙여넣기·원격 파일 삭제 등 적용 범위 |
| SEC-P06 | 앱 실행·세션 연결·네트워크 재연결·원격 명령 실행 사이의 사용자 동의 경계를 유지 | 행위별 동의 및 자동화 정책 |
| SEC-P07 | 저장소에 고객사 실서버 IP·비밀번호·개인키 등을 커밋하지 않고 가상 예제 사용 | S4 개발 보안 권고, 저장소 검사 절차 |

최초 지문 승인만으로 실제 서버 신원이 보장되지는 않는다. 단순 명령 문자열 감지로 모든 위험 명령을 판별할 수도 없다. 이 제약을 완전한 보안 보장으로 표현하지 않는다.

## 8 충돌 검토와 보완 후보

기존 요약은 직접적인 정책 모순이 발견되지 않았다고 보고했다. 본 문서에서는 STEP 01~07 원문 부재로 전체 무충돌 판정을 재확정하지 않는다.

| 검토 주제 | 남아 있는 문제 | S2의 제안 |

## 10 검증 기준과 완료 조건

### 10.1 대화에 제시된 MVP 완료 기준

아래는 S2 MVP 표의 완료 기준을 정리한 것이며 아직 실행 결과가 없다. MVP 범위 자체의 승인 상태는 6장을 따른다.

| ID | 검증 영역 | 완료 기준 |
|---|---|---|
| ACC-01 | 서버 관리 | 여러 서버 등록 및 빠른 탐색 가능 |
| ACC-02 | SSH 인증 | 지원 대상 서버에 안전하게 접속 가능 |
| ACC-03 | 호스트 검증 | 최초 승인 전 연결 금지 및 지문 변경 시 차단 |
| ACC-04 | 터미널 | vim·top·less 등 대화형 도구 정상 사용 |
| ACC-05 | 세션 | 한 세션의 장애가 다른 세션에 영향 없음 |
| ACC-06 | 붙여넣기 | 승인 전에 대상 서버로 전송하지 않음 |
| ACC-07 | 데이터 | 재실행 후 설정 보존 및 비밀정보 노출 없음 |
| ACC-08 | 보안 | 정해진 보안 테스트 통과; 상세 목록은 원문 확인 필요 |
| ACC-09 | 실행 환경 | macOS M2에서 설치·실행 정상, 세션 자동 연결 없음 |

### 10.2 첫 연결 개발 마일스톤

S4의 개발 권고는 앱의 MacBook M2 실행, 테스트 Linux 서버에 대한 안전한 SSH 연결, 호스트 키 확인 및 인증, hostname·whoami·uptime 실행과 결과 표시, 세션 종료 시 자원 정리를 성공 조건으로 제시한다. 이는 초기 구현 검증안이며 전체 제품의 완료 기준을 대체하지 않는다. 로컬 VM 또는 별도 테스트 서버 사용이 권고되었다.

### 10.4 완료 판정

**요구사항 문서 완료:** STEP 01~08 원문을 모두 확보하고 각 정책·예외·기본값·수치·후속 범위를 요구사항 ID에 대조한다. 누락된 통합 목록과 시험 목록을 보완하고, 제안이 확정 정책으로 잘못 분류되지 않았는지 확인한 뒤 문서 기준선을 승인한다. 이는 이번 문서의 검수 기준이다.

**MVP 완료:** 승인된 MVP 범위와 적용되는 완료 기준을 충족하고 시험 증거를 남긴다. 정식 출시 승인을 뜻하지 않는다.

**제품 v1.0 출시:** 확정 출시 정책에 따라 핵심 기능·보안·안정성 시험을 통과해야 한다. 단일 Jump Host의 첫 버전 포함 결정을 유지한다. 상세 출시 범위·호환성·성능 기준 및 원래 시험 목록을 대조하기 전에는 본 문서만으로 출시 완료를 선언하지 않는다.
